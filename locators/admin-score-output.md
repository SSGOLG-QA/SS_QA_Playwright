# 라운드 관리 > 스코어 출력 설정 (신규 화면)

> **학습 근거**: 기획서 이미지(2026-08-18 제공) + 운영이슈 R84~85(스코어 출력 여백/인쇄). 라이브 DOM 미캡처 → **locator는 기획서+컨벤션 기반 설계값(⚠ 라이브 확인 필요)**. 확정 캡처: `Admin/_probe-score-output.spec.ts`(`npm run auth` 후 실행 → `analysis/라운드관리_스코어_출력_설정.json`).
> **비파괴 원칙**: 저장·[이동하기]·토글 실변경·[사진선택]·미사용 전환 저장은 **상태 변경** → 노출·활성만 검증. 상태 의존(사용/미사용) 요소는 조건부 검증 또는 skip.

## 개요
- **위치**: SNB `라운드 관리` 최하위 신규 메뉴 **`스코어 출력 설정`** (내장 현황·전체 라운드·단체 라운드·라운드 설정·카트 관리·홀별 정산 관리 **다음**).
- **목적**: 골프장별 **스코어카드 출력 서비스**(고객이 태블릿/PC에서 스코어카드 출력) 사용 여부·로고·본인확인 방식 설정. 저장 시 해당 골프장 출력 서비스 페이지에 **즉시 반영**.
- **URL**: **`/club/page/scorecard-print-setting`** ✅(2026-08-18 라이브 확정). 출력 서비스 자체 URL = `print.smartscore.global/{골프장 전용URL}` (키오스크 모드).
- **SNB 순서**(라이브): 내장 현황·내장 통계·전체 라운드·단체 라운드·라운드 설정·홀별 정산 관리·카트 관리·**스코어 출력 설정**·마커 인증 조회(마커 인증 조회도 신규).
- **상태 2종**:
  - **세팅 전(초기/미사용)**: ①제목+안내 · ②바로가기 · ③사용여부 토글(초기값 **미사용**) · ⑥저장. **로고(④)·본인확인(⑤) 미노출**.
  - **세팅 후(사용)**: ③토글 `사용` → **④로고 등록 · ⑤본인확인 방식 추가 노출**.
- **API 암호화 필요**: 라운딩 정보, 스코어 카드.

### 기획-구현 차이(diff 확정)
1. **토글 라벨**: 기획 `미사용/사용` → 구현 **`미노출/노출`**(안내도 "미노출 시…노출 시…").
2. **로고 버튼**: 기획 [사진선택]/[사진 미리보기] → 구현 **[사진등록] 추가**(등록 확정 분리).
